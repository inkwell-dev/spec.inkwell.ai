# Report figures

PlantUML sources for the figures in the PFE report. Text, so they live in git
next to the specs, diff when the system changes, and can be re-rendered at any
size without redrawing.

## Which tool for which figure

**PlantUML** for anything whose layout auto-layout can hold: class and sequence
diagrams. Text source, regenerable when the schema moves. The class diagrams use
`!pragma layout elk`: straight, right-angled links that do not cross, where
Graphviz drew curves through each other.

**Use case diagrams: PlantUML content, generated draw.io layout.** Each
`fig-*-use-case-*/` folder keeps its `.puml` as the source of the actors, use
cases, relations and notes, but `tools/gen-use-cases.py` draws the figure into a
`.drawio` file and PlantUML no longer renders it. The generator fixes the shape
Graphviz could not hold: the actors stacked in one column on the left, the use
cases in columns to the right, a link across columns routed through its own lane,
notes under the boundary. After editing a use case `.puml`, run `make regen`
then `make one F=<figure>`.

**The global use case diagram is the exception.** After the supervisor's review,
`fig-1-11-use-case-global.drawio` is laid out by hand in draw.io: actors in a row
along the top, each base use case with its extensions beside it, and every
authenticated use case drawn with an explicit `«include»` to *Sign in*. That
include is meant to stand out, so no note replaces it. The `.puml` beside the
drawing holds the same content as text and is kept in step **by hand**, so edit
both together. `make regen` touches neither, and `tools/gen-use-case-global.py`
is retired. In draw.io, write the stereotypes as `«include»` and `«extend»`, not
`<<…>>`.

**The complete class diagram is edited in draw.io and re-laid out on demand.**
`fig-1-12-classes-global.drawio` is the source: change a class there.
`tools/gen-class-global.py` reads the classes from that drawing, takes the
associations from its own list (which follows `src/database/schema/`), and
rewrites both the drawing and `fig-1-12-classes-global.puml`, so the two never
disagree. It is **not** part of `make regen`, because it overwrites the drawing
it reads: run it by hand and review the result. After the supervisor's review
the layout follows a few rules: every multiplicity and name sits on its line in
an opaque box; User and Article are drawn as tall as their neighbour columns so
that facing classes join with straight lines; each gap between columns is as
wide as its lanes need; and the many-to-many associations with data of their
own (Like, Save, Repost, CommentLike, Follow, Block) are association classes,
each next to its line. The older hand layout,
`fig-1-12-classes-global-friend-layout.drawio`, is kept for reference only.

**draw.io** (generated by a Python script, then exported by the CLI) for figures
where placement *is* the content: the method and architecture figures.

The dividing line was found the hard way. The global use case diagram was
attempted four times in PlantUML: with include/extend relations, Graphviz drags
every dashed target outside the system boundary, and at 16 use cases the figure
spreads to 2091×957 with the actors scattered. Hand-placing it fixes containment,
gives the ordered actor column, and lets all eight `«include»` arrows to *Sign
in* be drawn — which is what the example report does per sprint.

## Layout

One folder per figure, named after the figure, holding its source and its two
renders:

```
diagrams/
├── _style.puml                          shared style, included by every .puml
├── Makefile
├── tools/                               the draw.io generators
│   ├── gen-method-figures.py
│   ├── gen-actors.py                    the actors infographic
│   ├── gen-architecture.py              the four architecture figures
│   └── gen-use-cases.py                 use case .puml → laid-out .drawio
└── fig-5-4-sequence-ai-chat-rag/
    ├── fig-5-4-sequence-ai-chat-rag.puml
    ├── fig-5-4-sequence-ai-chat-rag.svg
    └── fig-5-4-sequence-ai-chat-rag.png   (ignored by git)
```

A figure's folder name, source name and caption number all match, so a figure
referenced in the report resolves to exactly one directory.

## Rendering

```bash
make                                       # everything, both tools
make one F=fig-5-4-sequence-ai-chat-rag    # a single figure, either tool
make check                                 # parse the PlantUML sources
make regen                                 # re-run the draw.io generators
make clean
```

Docker is the only requirement — `plantuml/plantuml` carries PlantUML 1.2026.6
and Graphviz 14. Nothing is installed on the host.

**Use the SVG in the report.** It is vector: it scales to any column width
without resampling, and both LaTeX (`\includegraphics`) and Word accept it. The
PNG is for quick review only. PDF export does not work in this image (missing
jars) and is not needed.

## House style — matched to the example report

Derived from 38 figures extracted from the example report (Wael Abidi / AI
Algora) on 2026-08-19. `_style.puml` encodes all of it; these are the rules
behind the settings, so a new diagram can be checked against them.

| Aspect | Rule |
|---|---|
| UML colour | **Black on white. No fills, no brand colour** |
| Colour | Reserved for architecture and infrastructure figures, drawn in draw.io |
| Actors | Default stick figure, bold label below, generalisation arrows pointing up to the general actor |
| Actor placement | One ordered column — forced with `-[hidden]down-`, since they hand-place theirs |
| System boundary | Plain rectangle, labelled `<< System >>` on the global diagram only |
| External systems | Plain rectangles **outside** the boundary, joined by solid lines |
| Per-sprint use case refinement | Sub-use-cases point at the parent with hollow generalisation triangles |
| Enumerations | Separate `<<Enumeration>>` boxes, header `#DAE8FC`, unconnected, grouped to one side in a 3×3 block |
| Class attributes | `- name : Type`, **no visibility icons** (`classAttributeIconSize 0`) |
| Attribute types | Domain types — String, Integer, Boolean, Timestamp, Json, Vector |
| Sequence frame | `mainframe interaction SequenceDiagram <name>` — the pentagon tab |
| Sequence participants | Rectangles, **including the human actor** (`participant`, never `actor`) |
| Authentication | Factored into a `ref over` fragment at the top |
| Branching | `alt` with unbracketed guards — PlantUML adds the brackets; writing them yourself is parsed as creole and renders as a blue link |
| Messages | `autonumber "0 :"` gives their `N : label`; solid call, dashed open-arrow return |
| Activation | `activate` / `deactivate` on every participant that does work |
| Notes | Yellow `#FFF2CC`, italic |

### Two deliberate deviations

1. **No methods compartment.** Their classes are Mongoose documents with real
   methods (`getProfile()`, `addMember()`). Ours is a relational schema where
   behaviour lives in the NestJS service layer, so inventing methods on a table
   would be fiction. `hide methods` is set, and the report says why in one line.
2. **Types are abstracted, not raw DDL.** `JSONB` reads as `Json`, `vector(1536)`
   as `Vector`, `timestamptz` as `Timestamp` — their convention is domain types,
   and this stays truthful while matching it. The real column types remain in
   `6-database-schema.md`.

## Conventions

- One file per figure, named `fig-<chapter>-<number>-<slug>.puml`, so the
  filename matches the caption `Figure X.Y – Titre`.
- Every file starts with `!include _style.puml`, which holds the palette from
  `9-design.md` §3.2. Change the style once, re-render, and all figures move
  together.
- Diagram text is **English**: the report is written in English, so labels go in
  verbatim. The two example reports are French, but they supply the structure,
  not the wording.

## Layout notes

Graphviz places nodes automatically and sometimes needs persuading. The knobs
that actually help, in order:

1. **`-[hidden]down-` chains** to stack leaf classes into columns. This is the
   single most effective lever on any hub-and-spoke diagram: it took
   `fig-2-3` from 2784×405 to 1463×1014.
2. `left to right direction` for wide figures; omit it for tall ones.
3. `skinparam nodesep` / `ranksep` for density.
4. Split a *global* diagram by actor group rather than coarsening it. After the
   supervisor's review the single global diagram (`fig-2-1`, bundled use cases
   such as "Interact (like, comment, …)") was replaced by three — visitor and
   reader, writer, magazine and administrator — with one action per use case.
   Put extensions and inclusions on the right of their base (`BASE <.. EXT`,
   `BASE ..> INC`) so the actor's links only reach the first column.

Budget a few minutes per figure for this. It is the real cost of the set.

## Two traps that cost real time

**In draw.io, never put `<<include>>` in a label.** Every shape style carries
`html=1`, so `<<include>>` is parsed as an HTML tag and silently disappears —
the edges render with no stereotype at all. Use the guillemets `«include»`,
which is the correct UML rendering anyway.

**Never write `skinparam padding`.** PlantUML renders a deprecation warning
*into the image* — a yellow banner across the top of every figure. It was in the
first draft of `_style.puml` and appeared in every render until removed.

**Parentheses in an attribute make PlantUML treat it as a method.** With
`hide methods` set, the attribute then silently disappears: `+content : JSONB
(TipTap)` and `+type : enum (8 valeurs)` both vanished from the first class
diagram. Prefix such lines with `{field}` — eight lines across the two class
diagrams need it.
